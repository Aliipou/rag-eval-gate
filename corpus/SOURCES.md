# Corpus sources

This corpus is real public-sector text, not synthetic filler. Two documents,
158 chunks total (see `corpus/data/chunks.jsonl`, generated by
`corpus/ingest/build_corpus.py`).

## 1. Constitution of Finland (731/1999)

- **Source**: Finlex (finlex.fi), the Finnish Ministry of Justice's public
  legal database.
- **Page**: https://www.finlex.fi/en/legislation/translations/1999/eng/731
- **PDF fetched from**: `https://www.finlex.fi/api/media/statute-foreign-language-translation/1070874/mainPdf/main.pdf`
- **Local cache**: `corpus/raw/constitution_731_1999.pdf`
- **Chunking**: one chunk per statute section (`Section N`), parsed from the
  `Chapter N` / `Section N` layout Finlex uses. 128 chunks, ids like
  `const-731-1999-s6`.
- **Licence / reuse**: Finlex publishes this as an *unofficial translation*
  ("Legally binding only in Finnish and Swedish", Ministry of Justice,
  Finland). The source page does not state a separate open-data/CC licence.
  It is reproduced here, with full attribution and a link back to the
  official page, for a non-commercial portfolio/demo project. Do not treat
  this corpus as a legally authoritative source of Finnish constitutional
  law -- always cite the official Finlex page for real use.

## 2. Guide to the Employment Contracts Act

- **Source**: Ministry of Economic Affairs and Employment of Finland
  (Työ- ja elinkeinoministeriö, tem.fi).
- **PDF**: https://tem.fi/documents/1410877/2918935/Employment+Contracts+Act/b0fca473-f224-46b9-974c-acd153587680
- **Local cache**: `corpus/raw/employment_contracts_act.pdf`
- **Chunking**: one chunk per PDF page (31 pages extracted, 30 kept after
  dropping near-empty pages), ids like `emp-guide-tem-p13`. This document is
  not laid out with numbered legal sections, so page-granularity chunking is
  used instead of section-granularity (see `corpus/ingest/gov_guide_pdf.py`
  for the rationale).
- **Important**: this is a ministry *guide explaining* the Employment
  Contracts Act in plain language, not the statute text itself. Treat
  citations to it as "the ministry's guidance says", not "the law says".
  This is why the golden set (`eval/golden.yaml`) has cases that
  deliberately probe this distinction.
- **Licence / reuse**: published as a public guidance PDF by a Finnish
  government ministry; no separate licence stated. Reproduced here with
  full attribution for a non-commercial portfolio/demo project.

## Ingestion is pluggable

`corpus/ingest/` has one module per *source shape*, not one per document:

- `finlex_statute.py` -- parses the `Chapter N` / `Section N` layout common
  to Finlex statute-translation PDFs. Works for any Finlex statute, not
  just the Constitution: resolve the statute's numeric "media id" from its
  `finlex.fi/en/legislation/translations/<year>/eng/<number>` page and pass
  it as `FinlexStatuteSource(media_id=...)`.
- `gov_guide_pdf.py` -- page-granularity chunking for prose PDFs without a
  reliable heading grammar.
- `base.py` -- the shared `Chunk` type both ingesters produce.

`build_corpus.py --live` re-downloads both PDFs from their live URLs
instead of using the `corpus/raw/` cache, then writes
`corpus/data/chunks.jsonl`. Everything downstream (retrieval index, eval
harness, MCP server) only ever reads that one committed JSONL file, so
refreshing the corpus never requires touching retrieval or eval code.

## Known quirk documented for whoever extends this

Finlex's media API returns HTTP 200 with `Content-Type: image/x-png` (a
placeholder image, not an error) when the numeric media id is stale or the
request lacks a browser-like `User-Agent`/`Accept` header. `fetch_pdf_bytes()`
in `finlex_statute.py` checks the response `Content-Type` explicitly and
raises rather than silently ingesting a PNG as if it were a PDF.

## What a live-pgvector / production setup would add

This project ingests a small, fixed sample (158 chunks) suitable for a
deterministic eval gate. Pointing the same ingesters at the *full* Finlex
statute book would mean: (1) iterating the statute index instead of two
hardcoded sources, (2) writing chunk embeddings into PostgreSQL + pgvector
instead of the in-memory/file-backed TF-IDF index this project uses (see
`rag/retrieval.py` and the README's "What is implemented / what is not"
section), and (3) re-running `eval/run_eval.py --record` against the larger
corpus to refresh golden-set fixtures.
